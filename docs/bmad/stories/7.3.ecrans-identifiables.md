# Story 7.3 — Écrans identifiables

**Statut :** Done
**Epic :** 7 · **Dépend de :** 7.1

## Story

**En tant que** consultant avec plusieurs écrans (dont deux V277U identiques),
**je veux** reconnaître chaque écran au démarrage et choisir le principal, tous les écrans, ou l'écran n,
**afin que** les captures montrent ce qui est partagé, et pas mon second écran.

## Critères d'acceptation

1. Quand « Capturer l'écran » est coché, la fenêtre propose :
   - « Écran principal » ;
   - « Tous les écrans (N) » ;
   - une carte par écran, avec miniature, « Écran n » numéroté de gauche à droite (puis de haut en bas), sa résolution et « principal » le cas échéant.
2. Le choix est mémorisé par **position** de l'écran (`pos:x,y`), pas par l'identifiant système. Un écran mémorisé qui a disparu retombe sur « Écran principal », avec un avertissement dans la fenêtre.
3. En mode « tous les écrans », les captures sont numérotées comme la liste : le suffixe `_eN` et le champ `monitor` suivent l'ordre gauche → droite.
4. Les miniatures (environ 240 px de large) sont produites à l'ouverture de la fenêtre, en moins d'une seconde, sans écriture sur disque.
5. Les anciennes valeurs `monitor:<id>` restent acceptées : rétrocompatibilité du réglage Cloud & IA.

## Tâches

- [ ] Rust `screen_capture.rs` : `ordered_monitors()` trie par (x, y). `MonitorInfo` gagne x, y, `key` (`pos:x,y`) et `number`. Commande `api_monitor_thumbnails` (data URL JPEG).
- [ ] `capture()` : résolution de `pos:x,y` (et de `monitor:<id>`), numérotation par la position.
- [ ] Interface : cartes avec miniatures dans `RecordingSourcesPicker`, avertissement si l'écran mémorisé est absent ; le réglage Cloud & IA utilise les mêmes clés.
- [ ] Tests Rust : tri par position, résolution des clés et repli.
